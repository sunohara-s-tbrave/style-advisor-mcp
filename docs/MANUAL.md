# AIチャットツール作成マニュアル

Claude（AI）を使った「自分専用のAIチャットツール」を作り、社内に配布するまでの手順です。
例として「洋服のコーディネート相談」ツール（本リポジトリ）を作りましたが、
**中身（テーマ・参考資料・AIへの指示）は自由に差し替えられます**。
社内規程のQ&A、業務手順の案内、定型文書の下書きなど、業務向けにもそのまま応用できます。

---

## 1. できあがるもの

- ブラウザで使うチャット画面（自分のPC上で動く。URLは `http://localhost:4319`）
- AIが回答するときに参照する **参考資料**（JSONファイル）
- 会話で分かったことを覚えておく **メモ機能**（PC内の `profile.md` に保存）
- ダブルクリックだけで起動できる **ランチャー**（非エンジニアに配る用）

## 2. 全体の仕組み

```
[ブラウザのチャット画面]  web/public/
        │ メッセージ送信
        ▼
[Webサーバー]  web/src/server.ts
  - AIへの指示（システムプロンプト）を持つ
  - Claude Agent SDK で、利用者のPCにログイン済みの Claude を呼び出す
        │
        ▼
[Claude（AI）] ── 必要に応じて参照・呼び出し ──▶ [MCPサーバー]  src/
                                                  - 参考資料（Resources）: src/data/*.json
                                                  - メモの読み書き（Tools）: profile.md
               ── 必要に応じて ──▶ Web検索（WebSearch / WebFetch）
```

**ポイント：判断はAIに任せ、MCPサーバーには「資料」と「道具」だけを持たせる。**
診断ロジックなどをコードで書き込まないため、テーマを変えたいときも
「資料（JSON）」と「AIへの指示（システムプロンプト）」を差し替えるだけで済みます。

| 用語 | このツールでの意味 |
|---|---|
| システムプロンプト | AIの役割・話し方・守るルールを書いた指示文 |
| MCPサーバー | AIに資料や道具を渡すための小さなプログラム |
| Resources（参考資料） | AIが読みに行ける資料。JSONに書いた内容をMarkdownにして渡す |
| Tools（道具） | AIが呼び出せる機能。ここではメモの読み書き |
| Claude Agent SDK | 自分のプログラムからClaudeを呼び出すためのライブラリ |

## 3. 準備するもの

| もの | 用途 |
|---|---|
| Node.js v20以上 | プログラムの実行（https://nodejs.org/ から入手） |
| Claude のアカウント | AIの利用。利用者それぞれがログインする（または `ANTHROPIC_API_KEY` を設定） |
| Claude Code | 作成作業をAIに手伝ってもらうためのツール（なくても作れるが、あると大幅に楽） |

> 本ツールは **Claude Code に指示を出しながら作成しました**。
> 以下の各手順に「Claude Code への指示例」を載せているので、そのまま使えます。

## 4. 作成手順

### ステップ1：テーマとルールを決める

作り始める前に、次の3点を文章にしておきます。これがAIへの指示の元になります。

1. **AIの役割**：何の相談に乗るのか（例：スタイルアドバイザー／社内規程の案内係）
2. **参考資料**：AIに読ませたい情報は何か（例：シーン別の服装の目安／就業規則・経費精算の手順）
3. **守らせたいルール**：言ってはいけないこと、必ずやること
   （例：ネガティブな表現を使わない／資料にないことは推測で答えず担当部署を案内する）

あわせて、開発時のルールを `CLAUDE.md` に書いておくと、Claude Code が毎回それを守って作業してくれます。
本リポジトリの `CLAUDE.md` が実例です（「`console.log` 禁止」「個人情報はローカル保存のみ」など）。

### ステップ2：MCPサーバーの土台を作る

**Claude Code への指示例**

> TypeScript で MCP サーバーを作ってください。トランスポートは stdio。
> `src/index.ts` で起動、`src/server.ts` にサーバー本体、`src/resources/` と `src/tools/` に機能を分けてください。
> 標準出力はMCPの通信に使うので、ログは必ず `console.error` にしてください。

できあがる主なファイル：

- `src/index.ts` … 起動処理
- `src/server.ts` … Resources と Tools を登録する場所
- `package.json` / `tsconfig.json` … 設定

> **注意**：stdio方式では標準出力（`console.log`）がAIとの通信そのものです。
> `console.log` を書くと通信が壊れるので、ログは必ず `console.error` を使います。

### ステップ3：参考資料（Resources）を作る

1. `src/data/` にJSONで資料を書く。例：`src/data/occasions.json`

   ```json
   {
     "business": {
       "label": "通勤・オフィスカジュアル",
       "guideline": "信頼感と清潔感を軸に、色数は3色以内にまとめると印象が整う。",
       "goodPoints": ["ジャケットやきちんと感のあるブラウス", "..."]
     }
   }
   ```

2. `src/resources/` に、そのJSONをAIが読める形（Markdown）で渡すコードを書き、`src/server.ts` で登録する。
   資料は `style://occasions/business` のようなアドレスでAIから読めるようになります。

**Claude Code への指示例**

> `src/data/occasions.json` の内容を、`style://occasions/{occasion}` というURIで読める MCP Resource として登録してください。
> 中身はMarkdownに整形して返し、存在しないキーを指定されたらエラーにしてください。
> データとコードは分け、JSONに項目を足すだけで資料が増えるようにしてください。

> **コツ**：資料（JSON）と登録コード（`resources/*.ts`）を分けておくと、
> あとから資料を足すときにプログラムを触らずに済みます。

### ステップ4：メモ機能（Tools）を作る（任意）

会話で分かったこと（好み・よく使う場面など）を覚えておき、次回の会話で聞き直さないようにする機能です。
`src/tools/profileNotes.ts` に、次の2つを用意しています。

- `get_profile_notes` … `profile.md` を読む
- `save_profile_notes` … AIが書いた内容で `profile.md` を丸ごと上書きする

保存先は利用者のPC内だけです。`profile.md` は `.gitignore` に入れ、リポジトリに含まれないようにしています。

**Claude Code への指示例**

> AIが会話で分かったことを保存できるよう、`get_profile_notes`（読む）と `save_profile_notes`（全文上書き）の2つのツールを作ってください。
> 保存先はリポジトリ直下の `profile.md` にして、`.gitignore` に追加してください。

### ステップ5：テストと動作確認

```bash
npm install
npm run build
npm test            # 自動テスト（tests/ 配下）
npm run inspector   # MCP Inspector（ブラウザ）で Resources / Tools を手で試す
```

**Claude Code への指示例**

> 各 Resource と Tool について、vitest でテストを書いてください（正常系と、存在しないキーを指定したときのエラー）。

### ステップ6：チャット画面（Web版）を作る

`web/` フォルダに、ブラウザで使うチャット画面とそのサーバーを作ります。

- `web/public/`（`index.html` / `app.js` / `style.css`）… チャット画面
- `web/src/server.ts` … `/api/ask` でメッセージを受け取り、Claude Agent SDK でAIを呼び出して返事を返す

`web/src/server.ts` で設定している主な項目：

| 項目 | 内容 |
|---|---|
| `SYSTEM_PROMPT` | AIへの指示（次のステップで書く） |
| `mcpServers` | ステップ2〜4で作ったMCPサーバーを接続 |
| `tools` / `allowedTools` | AIに使わせる機能を限定（Web検索、資料の読み込み、メモの読み書きだけ） |
| `settingSources: []` | PC上の他の設定（CLAUDE.md など）を読み込まず、このアプリの指示だけで動かす |
| `resume` | 会話の続きを覚えておく（同じ画面での会話がつながる） |

**Claude Code への指示例**

> `web/` に、ローカルで動くチャット画面を作ってください。バックエンドは Express と Claude Agent SDK。
> `POST /api/ask` でメッセージを受け取り、`dist/index.js` のMCPサーバーを接続して Claude に回答させてください。
> 使えるツールは WebSearch / WebFetch / MCPのResource読み込み / メモの2ツールだけに限定してください。
> 会話の続きが保てるよう、セッションIDで resume してください。ポートは 4319。

> **注意**：MCPのツールを許可するときは、`mcp__サーバー名__*` のようなワイルドカードではなく、
> ツール名を1つずつ列挙してください（ワイルドカードは確実に効かないことがあります）。
> ツールを追加したら `MCP_SERVER_TOOLS` にも追記が必要です。

### ステップ7：AIへの指示（システムプロンプト）を書く

ツールの出来を一番左右するのがここです。`web/src/server.ts` の `SYSTEM_PROMPT` に書きます。
本ツールでは、次のような見出しで整理しています。

- **役割**：「あなたは経験豊富なスタイルアドバイザーです」
- **返信の長さ**：「1画面に収まる程度」「選択肢は2つまで」
- **会話の進め方**：「一度に何個も質問しない」「提案を求められたら、質問より先に提案する」
- **参考資料の使い方**：どの資料を、どんなときに読むか（Resourceのアドレスを列挙）
- **メモの使い方**：会話の最初に読む、分かったことがあれば保存する
- **やってはいけないこと**：「検索していない商品名・価格を作り出さない」「ネガティブな表現を使わない」

**書き方のコツ（実際に使ってみて効いたもの）**

1. **「〜しないで」より「〜して」を具体的に書く。** 例：「提案 → 確認の質問、の順にする」
2. **一番守らせたいルールには「最優先」と明記する。** AIはルールが衝突したときに迷うため。
3. **事実に関わる部分は、根拠を必ず確認させる。** 例：実在の商品は必ずWeb検索してから紹介する。
   業務版なら「資料に書いてあることだけを答え、出典を添える。書いていなければ担当部署を案内する」。
4. **実際に何度も会話して、気になった返事を見つけたら、その都度ルールを1つずつ足す。**
   本ツールの「返信は短く」「質問の後に安心させる一言を付けない」などは、試用して足したルールです。

### ステップ8：配布用ランチャーを作る

エンジニアでない人でも使えるよう、ダブルクリックで起動するファイルを用意しています。

| ファイル | 対象 |
|---|---|
| `Style Advisor を起動.command` | Mac |
| `Style Advisor を起動.bat` ＋ `launcher.ps1` | Windows |

ランチャーは次の順に処理します。

1. Node.js が入っているか確認（なければ公式サイトを開く）
2. 初回のみ、必要なものをインストールしてビルド
3. Claude にログイン済みか確認（未ログインならログイン画面を開く）
   ※ `web/scripts/claude-bin-path.mjs` で、SDKに同梱されている Claude を探して使う。別途インストールは不要
4. サーバーを起動し、ブラウザで `http://localhost:4319` を開く

**Claude Code への指示例**

> 非エンジニアがダブルクリックだけで使えるよう、Mac用の `.command` と Windows用の `.bat` + PowerShell のランチャーを作ってください。
> Node.js の確認、初回の npm install とビルド、Claude のログイン確認、サーバー起動、ブラウザ起動まで自動で行い、
> エラー時は日本語で案内して、詳細は `launcher.log` に書き出してください。

## 5. テーマを差し替えて別のツールにする

例：「社内規程Q&Aアシスタント」にする場合に変更する箇所です。

| 変更する箇所 | 変更内容 |
|---|---|
| `src/data/*.json` | 服装の資料を削除し、規程・手順の資料（例：`expenses.json`, `leave.json`）を置く |
| `src/resources/*.ts` | 資料のアドレスを `policy://expenses` などに変更 |
| `src/server.ts` | 登録する Resource を差し替え、サーバー名を変更 |
| `src/tools/profileNotes.ts` | 不要なら削除。使うなら保存内容を「部署」程度に絞る |
| `web/src/server.ts` | `SYSTEM_PROMPT` を業務用に書き直す。`MCP_SERVER_NAME` / `MCP_SERVER_TOOLS` を合わせる。Web検索が不要なら `tools` から外す |
| `web/public/index.html` | 画面のタイトルや見出し（「今日は何を着ましょうか？」など）を変更 |
| ランチャー・`README.md` | ツール名を変更 |
| `tests/` | 新しい資料に合わせてテストを直す |

**Claude Code への指示例**

> このリポジトリを「社内規程Q&Aアシスタント」に作り替えてください。
> 仕組み（MCPサーバー＋Web版＋ランチャー）はそのままにして、服装関連の資料・プロンプト・画面の文言を差し替えます。
> 資料は `src/data/` に置いた規程のJSONだけを根拠に答え、回答には出典（どの資料か）を添え、
> 資料にないことは推測で答えずに担当部署を案内するよう、システムプロンプトを書いてください。

## 6. 注意点

- **社内資料を入れるときは、入れてよい範囲を事前に確認する。** 資料の内容はAI（Claude）に送られます。
- **個人情報は必要最低限に。** 本ツールのメモは利用者のPC内にだけ保存し、外部送信やDB保存はしていません。ログにも出しません。
- **AIの回答は間違うことがある。** 事実に関わる部分は、資料や検索結果を根拠にさせ、利用者にも「目安」であることを伝える。
- **利用者それぞれに Claude のアカウント（またはAPIキー）が必要。** 利用料の扱いは事前に確認する。

## 7. 未対応・今後の課題

- **コード署名に未対応。** 初回起動時にMac/Windowsのセキュリティ警告が出る
  （Mac：Controlキーを押しながらクリック →「開く」／Windows：「詳細情報」→「実行」）。
- **Windows版ランチャーは実機で未検証。** 配布前に必ず動作確認が必要。
- **Node.js は同梱していない。** 利用者のPCに初回のみインストールが必要。
- **ローカルで動く前提。** 複数人で1つのサーバーを共有する形（社内サーバーへの設置など）には未対応。
